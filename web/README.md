# CourseCheck Web

CourseCheck의 배포용 웹앱입니다. 2026학년도 2학기 개설과목 1,494개를 정규화해 일반 전공과 연계전공별 시간표를 만듭니다.

## 실행

```bash
npm install
cp .env.example .env.local
npm run dev
```

## 확인

```bash
npm test              # 빌드 + 렌더링·파서·수강자격·이벤트 정합성 테스트
npm run lint
npm audit --omit=dev
```

## 데이터와 설정

- `app/data/courses.generated.json`: SIS 원본에서 생성된 배포 데이터
- `app/data/majors.ts`: 연계전공 과목표와 공식 출처
- `app/data/core-curriculum.mjs`: 요람 〈별표 1〉 기준 학번별 필수 교양 트랙
- `app/data/equivalents.mjs`: 요람이 「택1」·「중복 수강 불가」로 묶은 동일 인정 과목
- `app/data/affiliations.mjs`: 학과→대학 매핑과 소속별 수강 자격 판정
- `app/lib/sis-parse.mjs`: SIS `.xls`(실제로는 HTML 표) 파서 — CLI와 업로드가 공유
- `scripts/import-sis.mjs`: 파일을 `courses.generated.json`으로 굽는 CLI
- `db/schema.ts`: 최소 사용자 설정과 익명 운영 이벤트 스키마
- `drizzle/`: Neon PostgreSQL에 적용되는 마이그레이션
- `scripts/deploy-check.mjs`: 배포 전 점검 — 지저분한 작업 트리·미푸시 커밋·빠뜨린 마이그레이션을 막습니다
- `app/api/health/route.ts`: 지금 떠 있는 배포의 버전과 커밋 해시

## Vercel + Neon 배포

1. Git 저장소를 Vercel Hobby 프로젝트로 가져옵니다.
2. Vercel Marketplace에서 Neon을 설치하고 프로젝트에 연결합니다.
3. Vercel이 만든 `DATABASE_URL` 환경 변수를 로컬로 내려받습니다.
4. `npm run db:migrate`로 최초 테이블을 만든 뒤 배포합니다.

```bash
vercel env pull .env.local
npm run db:migrate
vercel --prod
```

`drizzle-kit migrate`는 `@neondatabase/serverless` HTTP 드라이버로는 아무 것도 적용하지 않고 종료 코드 0을 반환합니다. 적용 후에는 반드시 컬럼이 실제로 생겼는지 확인하고, 적용되지 않았다면 `drizzle/*.sql`을 직접 실행한 뒤 `drizzle.__drizzle_migrations`에 `(sha256(파일 내용), _journal.json의 when)`을 넣어 주세요.

`DATABASE_URL`은 저장소에 올리지 않습니다. Preview와 Production 환경에도 같은 이름으로 연결해야 합니다.

## 배포 버전 관리

`vercel --prod`는 **로컬 폴더를 그대로 올립니다.** 커밋하지 않은 수정본이나 원격에 없는 커밋도 그대로 올라가므로, 그냥 두면 "지금 떠 있는 화면 = 어느 커밋"이 성립하지 않습니다. 그래서 두 가지를 둡니다.

**1. 배포 전 점검** — 작업 트리가 지저분하거나 `origin`에 올리지 않은 커밋이 있으면 배포를 막습니다. 스키마만 고치고 마이그레이션을 빠뜨린 경우도 잡습니다.

```bash
npm run deploy
```

`npm run deploy:check`만 따로 돌려도 됩니다. 점검을 건너뛰고 싶으면 `vercel --prod`를 직접 부르면 되지만, 그때 새겨지는 커밋 해시는 믿을 수 없습니다.

**2. 배포된 코드 확인** — 빌드할 때 커밋 해시를 화면에 새깁니다. 푸터에 `v0.1.0 · abc1234`로 보이고, 기계로 확인할 때는 다음을 씁니다.

```bash
curl -s https://<배포 URL>/api/health
```

```json
{ "version": "0.1.0", "revision": "abc1234", "builtAt": "2026-08-05T...", "environment": "production" }
```

로컬 빌드에서 커밋하지 않은 변경이 있으면 `abc1234-dirty`로 표시됩니다.

**Git 연동을 권합니다.** Vercel 프로젝트를 GitHub 저장소에 연결하면 푸시가 곧 배포가 되고, 각 배포에 커밋·브랜치가 자동으로 붙어 대시보드에서 롤백 대상을 고를 수 있습니다. CLI 배포는 이 연결이 없어 배포 목록에 URL만 남습니다. 공개 전에는 `git tag v0.1.0`처럼 되돌아갈 기준점도 하나 찍어 두세요.

## 운영 통계

`GET /api/stats`는 **관리자 전용**입니다(세션 없으면 401). 사용자 수와 이벤트 이름별 합계를 반환합니다. 공개 통계 엔드포인트는 없고, 사용자 수를 화면에 표시하지도 않습니다.

프로필 원본 행은 어디에도 공개하지 않습니다. 이름, 전체 학번, IP, 사용자 에이전트, 에브리타임 링크 또는 토큰은 앱 데이터베이스에 저장하지 않습니다.

## 첫 방문 설정과 학번별 요람

첫 방문 시 입학 연도, 이수학기 수, 소속 대학, 1·2·3전공을 저장합니다. 전공 입력은 현재 개설과목 학과명과 연계전공 목록을 검색하는 자동완성 방식이며, 저장된 값은 다음 방문 때 필터로 복원됩니다. 본문에는 전공 선택 단계를 두지 않고, 저장된 전공을 그대로 필터 조건으로 씁니다.

`app/data/core-curriculum.mjs`가 **2016~2026 요람 〈별표 1〉**을 그대로 담습니다. 입학 연도로 적용 요람을 고르고, 2016학년도보다 이전 학번은 보유한 첫 요람(2016)으로 안내합니다. 요람 안에서 늘거나 빠진 과목은 `from`(적용 시작 연도)과 `until`(마지막 인정 연도)로 표시합니다.

## 필수 교양 이수 판정

요람 체계가 2019학년도에 바뀌었으므로 트랙 구성도 두 갈래입니다.

| 적용 요람 | 체계 | 영역 |
| --- | --- | --- |
| 2016~2018 | 중핵필수 + 중핵필수선택 | 중핵필수 4개(읽기와 쓰기·글로벌 의사소통Ⅰ·서강인성·컴퓨팅 사고력) + 7개 탐구 영역 |
| 2019~2026 | 공통필수 + 공통선택 | 공통필수 5개(서강인성·글쓰기·글로벌 언어Ⅰ·전공·진로 탐색·소프트웨어) + 4개 영역 |

같은 체계 안의 학번별 차이도 요람 그대로 반영합니다. 예를 들어 소프트웨어 영역은 2019~2020학번 `컴퓨팅 사고력`, 2021학번 없음(공통필수 8학점), 2022학번부터 `기초인공지능프로그래밍`입니다.

판정 흐름:

1. 에브리타임에서 가져온 과목명을 트랙별 지정 과목명(과거 과목명 포함)과 비교해 이수 여부를 추정합니다.
2. 사용자가 트랙별 체크박스로 추정 결과를 덮어씁니다.
3. 이수한 트랙의 과목은 개설 시간표에서 제외하고, 남은 트랙의 과목은 전공 과목과 함께 보여줍니다.

체크 결과는 브라우저 상태로만 두고 서버에 보내지 않습니다.

### 소속 대학 기반 자동 판정

`colleges`에 소속별 계열(`stream`)과 요람이 지정한 영역별 필수선택(`pinned`)을 담아 두 가지를 자동으로 좁힙니다.

- 글쓰기 영역: 인문계열 → `인문사회 글쓰기`, 자연계열 → `자연계 글쓰기`
- 영역별 필수선택: 자연과학·공과·소프트웨어융합대학 → `미적분학Ⅰ`, SCIENCE기반 자유전공학부 → `과학도를 위한 파이썬`, 인문학기반 자유전공학부 → `인문학의 세계`

소속을 입력하지 않으면 좁히지 않고 영역 과목을 모두 보여줍니다. 2018학번 이전 중핵필수선택은 모집단위별로 필수 영역 자체가 달라 판정하지 않고 안내만 합니다. 편입·국제·장애학생 예외도 판정하지 않습니다.

## 개발자에게 건의하기

오른쪽 아래 버튼을 누르면 챗봇 형태로 의견을 받습니다. **단방향 접수**입니다 — 분류와 본문만 보내고, 답장 수단(이름·이메일·연락처)은 입력받지도 저장하지도 않습니다. 공개 API는 `POST /api/feedback` 하나뿐이고 읽기 경로가 없습니다. 익명 방문자 기준 하루 10건까지 받습니다.

받은 건의는 `/admin`에서 관리합니다.

```bash
# 관리자 키 만들기 (Vercel 환경 변수 ADMIN_TOKEN에도 같은 값을 넣습니다)
openssl rand -base64 32
```

`/admin`에 키를 입력하면 키 자체가 아니라 `ADMIN_TOKEN`으로 `주제|만료시각`을 HMAC 서명한 값만 `HttpOnly` `Secure` `SameSite=Strict` 쿠키로 남습니다. 만료시각이 서명에 들어 있어 8시간이 지나면 같은 쿠키 값은 통하지 않습니다. 10분 안에 5회 틀리면 15분간 잠깁니다. 목록에서는 분류·본문·작성 시각과 함께 익명 방문자 ID로 이어 붙인 학번·소속을 참고용으로 보여주고, 각 건의를 `새 건의 → 확인 중 → 처리 완료`로 표시할 수 있습니다. `ADMIN_TOKEN`이 없으면 관리 API는 503으로 닫힙니다.

`/admin`은 세 탭입니다.

- **건의**: 받은 건의를 `새 건의 → 확인 중 → 처리 완료`로 관리
- **집계·로그**: 아래 참고
- **개설과목**: SIS 파일 업로드

집계·로그 탭에서 보는 것:

| 무엇 | 내용 |
| --- | --- |
| 요약 카드 | 재학생 수(전체·최근 24시간), 둘러보기 수, 이용 기록 동의 수, 지금 떠 있는 배포 커밋 |
| 이벤트 집계 | 이벤트별 전체·최근 24시간 합계 |
| 누가 쓰고 있나 | 설정을 저장한 사람의 소속 대학·학번 분포 |
| 전공 분포 | 전공별로 1·2·3전공 중 어디에 뒀는지까지 |
| 단위별 이벤트 | 소속 대학 / 1전공 / 학번 중 하나로 묶은 (행) × 이벤트(열) 표 |
| 최근 로그 | 최근 익명 이벤트 120건 |
| 로그 정리 | `30일 지난 것만` / `전체 초기화` |

**둘러보기**는 설정 화면에서 "지금 수강신청할 재학생은 아니에요"를 체크한 사람입니다. 화면 동작은 같고 집계에서만 갈라져, 졸업생·외부인이 재학생 지표를 부풀리지 않습니다.

**전체 초기화**는 `analytics_events`를 전부 지우며 되돌릴 수 없습니다. 공개 전 시험 기록을 비울 때 씁니다. 사용자 설정(`user_profiles`)과 건의(`feedback_messages`)는 지우지 않으므로, 그쪽도 비우려면 데이터베이스에서 직접 지워야 합니다.

이벤트에 붙는 사용자 속성은 **소속 대학·1전공·입학연도**이고, 설정 화면에서 **선택 동의를 한 사람에게만** 붙습니다. 동의하지 않으면 이벤트 이름과 묶음 값만 남고 단위별 표의 "미선택"에 모입니다. 사용자에게 보이는 설명은 `/privacy`에 있습니다 — 자세한 내용은 [`SECURITY.md`](SECURITY.md). 화면이 쏘는 이벤트 이름과 `/api/events`의 허용 목록이 어긋나면 그 이벤트는 400으로 조용히 사라지므로, 테스트가 양쪽이 같은지 확인합니다 — 새 이벤트를 붙일 때는 `app/api/events/route.ts`와 `/admin`의 `EVENT_LABEL`을 함께 늘리세요.

세 가지 로그가 서로 다른 곳에 있습니다.

| 무엇 | 어디 |
| --- | --- |
| 앱이 남긴 익명 이벤트 | `/admin` → 집계·로그 또는 `GET /api/stats` (둘 다 관리자 전용) |
| 서버 예외·요청 로그 | `vercel logs <배포 URL>` 또는 Vercel 대시보드 Logs |
| 로컬 개발 로그 | `npm run dev`를 띄운 터미널 |

## 개설과목 데이터 갱신

SIS의 [개설교과목정보](https://sis109.sogang.ac.kr/sap/bc/webdynpro/sap/zcmw9016?sap-language=KO)는 SAP WebDynpro 화면이라 초기 HTML에 과목이 한 건도 없고, 세션과 뷰 상태 토큰을 실은 상태 유지 POST로만 목록을 받습니다. 그래서 자동 수집 대신 **파일을 받아 씁니다.** 내려받은 `.xls`는 확장자만 엑셀이고 실제로는 HTML 표라서 엑셀 파서 없이 읽습니다.

갱신 방법이 두 가지입니다.

1. **관리 화면 업로드** (재배포 불필요) — `/admin` → 개설과목 탭에서 파일을 올리면 파싱해 `course_datasets`에 저장하고, 화면이 가장 최근 자료로 갈아탑니다. `GET /api/courses`가 이를 돌려주고, 올린 자료가 없으면 204를 주어 빌드에 포함된 기본 자료를 씁니다.
2. **CLI** (기본 자료 교체, 재배포 필요)

```bash
npm run data:import 2026-2-sis.xls
```

두 경로가 `app/lib/sis-parse.mjs`를 함께 쓰므로 결과가 같습니다. 파서는 필요한 열(`학년도`·`학기`·`학과`·`과목번호`·`과목명`)이 없거나 과목이 50개 미만이면 무엇이 문제인지 알려주며 거부합니다.

## 수강 자격 (복수전공 신청 전)

프로필에 2·3전공을 적어도 **복수전공 신청이 승인되기 전에는** 그 대학·학과로만 열린 과목을 신청할 수 없습니다. 프로필의 「복수전공 신청을 마쳤어요」 체크로 이를 구분하고, 미완료면 그 전공의 학과·대학을 소속으로 인정하지 않습니다. **1전공은 소속 그 자체이므로 항상 인정합니다.**

판정 근거는 개설교과목정보의 「수강신청 참조사항」입니다. 표기 네 가지의 뜻은 같은 필드의 자유 서술이 확인해 줍니다.

| 표기 | 건수 | 뜻 | 확인 문구 |
| --- | --- | --- | --- |
| `X(가능)` | 919 | X 소속만 가능 | — |
| `X(불가능)` | 196 | X 소속은 전공 순번 무관 불가 | 「컴퓨터공학과 제1전공, 제2전공, 제3전공자 불가능」 |
| `X(1전공 가능)` | 51 | X의 1전공자만 가능 | 「인공지능학과 제1전공자만 수강 가능」 |
| `X(1전공 불가능)` | 57 | X의 1전공자만 불가 | 「컴퓨터공학과 제1전공자 수강 불가능」 |

「전학년수강신청일에 … 수강신청 가능」류 23건은 자격이 아니라 신청 시기 안내이므로 판정에 쓰지 않습니다.

학과→대학 매핑은 2026 요람 목차의 페이지 범위로 복원했습니다. 표기에 같은 조직의 옛 이름이 섞여 있어(`커뮤니케이션대학` 56건 = 지식융합미디어대학) 별칭으로 모읍니다. 글로벌한국학부는 2024학번부터 로욜라국제대학, 그 전에는 지식융합미디어대학입니다.

**판정할 수 없으면 막지 않습니다** — 모르는 소속 표기 때문에 들을 수 있는 과목을 감추는 쪽이 더 나쁩니다.

## 동일 인정 과목 (택1 묶음)

요람이 「택1」·「대체 인정」·「중복 수강 불가」로 묶어 둔 과목은 하나만 이수해도 나머지를 들을 필요가 없습니다. `app/data/equivalents.mjs`가 이 묶음을 담고, 제외 목록을 자동으로 넓힙니다. 예를 들어 `경영통계학`만 들었어도 `통계학입문`·`경제통계학`·`응용수학Ⅰ`·`사회통계학`이 함께 빠집니다.

묶음마다 `source`에 요람 원문을 적어 두었고, 근거를 찾지 못한 관계는 넣지 않습니다. 한 과목이 여러 묶음에 속할 수 있습니다 — `미적분학Ⅰ`은 「대학수학」 묶음과 「경제수리기초」 묶음 양쪽에 있습니다.

새 묶음을 추가할 때는 `data/bulletins/sogang-*.txt`에서 `택1`·`중복 수강`·`대체`·`동등한 과목`을 검색해 근거를 먼저 확보하세요.

## 결과 좁히기

- **전공 단위 제외**: 1·2·3전공별로 「이미 다 이수한 전공」을 체크하면 그 전공 과목이 한 번에 빠집니다.
- **교양 표시 전환**: `전체`(필수교양 + 자유교양 210과목) · `필수만`(기본, 남은 필수 교양 영역만) · `숨기기`(전공 과목만).

## 과목 구분 색

시간표와 목록의 색은 「그 과목을 무엇으로 듣는지」를 나타냅니다. 1전공 `#861f1c`, 2전공 `#004f8e`, 3전공 `#6f9453`, 필수교양 `#e3540b`, 자유교양 `#5c2976`. 판정 순서는 1·2·3전공 → 필수교양 → 자유교양이고, 결과에 실제로 있는 구분만 범례에 나옵니다.

## 내 시간표 (담기)

카드의 `+`를 눌러 과목을 담으면 `내 시간표` 뷰에 **시간 비례 캘린더**로 그립니다. `app/lib/calendar-layout.mjs`가 배치를 계산합니다.

- **10분 격자**: 개설과목의 시작 시각은 모두 15분 배수, 종료는 `11:50`·`18:50`만 예외라 10분 격자에 전부 정확히 맞습니다. 블록의 위치와 높이가 실제 시각·길이입니다.
- **레인 분할**: 같은 요일에 겹치는 수업은 열을 나눠 나란히 놓고 양쪽을 충돌로 표시합니다. 담은 과목은 보통 6~8개라 레인이 2~3개를 넘지 않습니다.
- **담은 과목은 브라우저에만** 둡니다(`localStorage`). 서버로 보내지 않습니다.

탐색용 「교시별 후보」 그리드를 캘린더로 만들 수 없는 이유는 아래에 있습니다.

## 시간표 행 묶기

행은 **시작 시각**으로만 묶습니다. 종료 시각까지 키로 쓰면 `13:30~14:45`와 `13:30~16:15`가 서로 다른 행이 되어 같은 교시가 갈라집니다 — 개설과목의 시작 시각은 19가지인데 (시작,종료) 조합은 69가지입니다. 각 과목의 종료 시각은 카드에 `~16:15`로 적습니다.

3전공 + 필수교양 기준으로 한 시점에 **최대 32과목**이 동시에 진행되므로(수요일 10:30), 탐색 뷰에서 캘린더식 레인 배치는 한 칸이 6px가 되어 쓸 수 없습니다. 그래서 교시 행 안에서는 카드를 세로로 쌓고, 캘린더는 담은 과목에만 씁니다.
