# Security & Privacy

CourseCheck는 학생의 수강 이력과 공개 시간표 링크를 민감한 정보로 취급합니다.

## 저장하는 정보

사용자가 동의하고 첫 설정을 완료하면 다음 항목만 Neon PostgreSQL에 저장합니다.

- 입학 연도(`22학번`은 `2022`로 저장)
- 이수학기 수
- 소속 대학 선택값(선택 항목, 입력하지 않으면 저장하지 않음)
- 2·3전공의 복수전공 신청 완료 여부
- 1·2·3전공 선택값
- 무작위 익명 브라우저 ID

익명 브라우저 ID는 `HttpOnly`, `Secure`, `SameSite=Lax` 쿠키로만 전달합니다. 사용자 수는 이 ID의 수로 집계하므로 여러 브라우저를 쓰거나 쿠키를 지우면 실제 인원과 차이가 날 수 있습니다.

## 저장하지 않는 정보

- 이름, 전체 학번, 이메일
- 에브리타임 공유 링크와 공유 토큰
- 에브리타임 원문 HTML/XML
- IP 주소와 User-Agent
- 개별 과목명 또는 전체 수강 이력
- 필수 교양 영역별 이수 체크 결과(브라우저 상태로만 유지)
- 건의를 남긴 사람의 이름·이메일·연락처(입력받지 않음)

위 항목은 CourseCheck 애플리케이션 데이터베이스에 기록하지 않습니다. 호스팅·네트워크 사업자가 자체 보안 및 운영 정책에 따라 보유하는 플랫폼 로그는 별도입니다.

## 개발자에게 건의하기

건의는 단방향으로만 받습니다. 저장하는 항목은 분류(정해진 4가지 중 하나), 본문(최대 1,000자), 처리 상태, 작성 시각, 익명 브라우저 ID입니다. 답장 수단은 입력받지 않으므로 저장할 것도 없습니다.

- 공개 API는 `POST /api/feedback` 하나뿐이며 읽기 경로가 없습니다.
- 익명 브라우저 ID 기준 24시간에 10건까지만 접수합니다.
- 요청 본문은 4KB, 본문 길이는 1,000자로 제한합니다.

관리 화면(`/admin`)과 관리 API는 `ADMIN_TOKEN`을 아는 사람만 접근할 수 있습니다.

- 키는 상수 시간 비교로 검증하고, 키를 URL·응답 본문·쿠키에 넣지 않습니다.
- 쿠키에는 `만료시각.서명`만 담고, 서명은 키로 `주제|만료시각`을 HMAC-SHA256 한 값입니다. **만료시각이 서명에 포함되므로 쿠키 값을 복사해 두어도 8시간이 지나면 통하지 않습니다.** 만료시각만 미래로 바꾸면 서명이 깨집니다.
- 쿠키는 `HttpOnly`, `Secure`, `SameSite=Strict`입니다.
- 로그인은 10분 안에 5회 틀리면 15분간 잠깁니다. 실패 응답은 일부러 늦춰 자동 대입 속도를 떨어뜨립니다.
- `ADMIN_TOKEN`이 설정되지 않은 배포에서는 관리 API가 503으로 닫힙니다.

로그인 시도를 묶기 위해 `admin_login_attempts` 테이블에 **원본 IP가 아니라 `ADMIN_TOKEN`으로 서명해 32자로 잘라낸 해시**와 시도 횟수만 저장하고, 로그인에 성공하면 그 행을 지웁니다. 이는 관리자 로그인에만 적용되는 예외이며 일반 사용자 요청에는 IP를 어떤 형태로도 기록하지 않습니다.

저장소가 공개되어 있어도 관리 화면은 열리지 않습니다. 코드를 복제해 각자 배포하면 그 사람의 데이터베이스와 그 사람의 `ADMIN_TOKEN`을 쓰는 별개 서비스가 되며, 이 배포의 환경 변수나 데이터에는 접근할 수 없습니다. 반대로 Vercel 프로젝트 권한이나 `DATABASE_URL`을 가진 사람은 관리 화면과 무관하게 데이터를 볼 수 있으므로, 두 값을 저장소·채팅·스크린샷에 남기지 않는 것이 가장 중요합니다.

## 운영 통계 공개 범위

`GET /api/stats`(사용자 수 + 이벤트별 합계)는 관리자 세션이 있어야 열립니다. 로그인 없이 볼 수 있는 통계 엔드포인트는 없으며, 사용자 수를 화면에 표시하지도 않습니다.

## 에브리타임 가져오기

- `https://everytime.kr/@…` 및 `https://everytime.kr/app/@…` 형식만 허용합니다.
- 호스트, 프로토콜, 토큰 문자를 서버에서 다시 검증합니다.
- 외부 요청 대상은 코드에 고정되어 있어 임의 URL 요청(SSRF)이 불가능합니다.
- 요청 본문, 응답 크기, 시간, 반환 과목 수에 상한을 둡니다.
- 공개 공유 페이지에서 과목명·교수·강의실만 읽고 원문과 링크는 응답 후 폐기합니다.
- 에브리타임의 로그인 비밀번호, 쿠키 또는 계정 권한을 요구하지 않습니다.

## 운영 로그

서비스 개선 목적의 다음 이벤트를 PostgreSQL에 기록합니다. 한 행은 **이벤트 이름 + 소속 대학 + 1전공 + 입학연도 + 묶음 값 + 시각**이고, 방문자 ID·IP·User-Agent는 어떤 형태로도 넣지 않습니다.

| 이벤트 | 함께 남는 묶음 값 |
| --- | --- |
| 첫 화면 열기 | – |
| 전공 설정 저장 | – |
| 개설 시간표 확인 | 결과 과목 수(`0`·`1-25`·`26+`) |
| 에브리타임 가져오기 | 가져온 과목 수(`0`·`1-5`·`6+`) |
| 에브리타임 실패 | – |
| 과목 담기 | – |
| 교양 표시 전환 | 고른 표시(`all`·`core`·`none`) |
| 건의 창 열기 | – |
| 도움이 됐나요 응답 | `yes`·`no` |

이벤트에 붙는 사용자 속성은 **소속 대학·1전공·입학연도**이고, **설정 화면의 선택 동의를 한 사람에게만** 붙습니다. 동의하지 않았거나 아직 설정을 저장하지 않았으면 이벤트에 이름과 묶음 값만 남습니다. 셋 다 허용 목록과 범위 검사를 거친 값만 저장하며, 이수학기 수와 2·3전공은 넣지 않습니다.

동의는 서비스 이용의 조건이 아닙니다. 동의하지 않아도 모든 기능을 똑같이 쓸 수 있고, 체크박스는 미리 켜 두지 않으며, 설정을 다시 열어 언제든 되돌릴 수 있습니다. 동의 문구에 **이 조합으로 개인이 짐작될 수 있다는 점**을 그대로 적어 둡니다 — 예를 들어 "인문대학·국어국문학과·22학번"에 해당하는 사람이 몇 명뿐이라면 그 칸은 사실상 소수의 행동 기록입니다. 그 위에 다음을 지킵니다.

- 이벤트 행에 **방문자 ID를 넣지 않습니다.** 어느 행이 누구인지, 같은 사람의 행끼리 무엇이 이어지는지 되짚을 수 없습니다.
- 관리 화면은 **합계만** 보여주고 원본 행을 개인별로 묶어 주지 않습니다.
- 이 표는 관리자 세션이 있어야 열립니다. 공개 엔드포인트는 사용자 수조차 내주지 않습니다.
- 오래된 기록은 30일 컷으로 정리하고, 전체 초기화도 관리 화면에서 할 수 있습니다.

목록에 없는 이름으로 들어온 이벤트는 400으로 거절합니다. 화면이 쏘는 이름과 서버 허용 목록이 어긋나면 집계에 조용히 구멍이 나므로, 테스트가 양쪽이 정확히 같은지 확인합니다.

`/api/stats`는 브라우저 기준 사용자 수와 이벤트별 합계만 공개하며 프로필 값이나 원본 행은 반환하지 않습니다. `/admin`에서 이벤트를 전부 지울 수 있고(되돌릴 수 없음), 30일이 지난 이벤트는 따로 정리합니다.

## 추가 방어

- API 요청 크기 제한 및 값 허용 목록
- 전공명 허용 목록 검증과 중복 전공 차단
- 프레임 삽입 차단, MIME 스니핑 차단, 최소 권한 브라우저 정책
- 링크 입력 자동완성 비활성화와 `no-store` 응답
- 데이터베이스 접속 문자열은 Vercel 환경 변수로만 관리
- 배포 의존성 기준 `npm audit --omit=dev` 0건 확인

보안 문제는 공개 이슈에 개인정보를 남기지 말고 저장소 관리자에게 비공개로 전달해 주세요.
